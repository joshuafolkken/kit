## `josh epic:plan` — EPIC の判断を計画段階に前倒しする

**この規則の単一ソースは [`.claude/skills/epic-commands/SKILL.md`](../../.claude/skills/epic-commands/SKILL.md) である。** ここに本文を複製しない（「クローン禁止・単一ソース化」の適用。joshuafolkken/kit#1174 のパイロットに続く横展開 joshuafolkken/kit#1189）。

`residency.md` が定めるとおり、`epic:plan` の手順は `epic:plan` を走らせた後にだけ効くので、手順本体は skill 側に置く。かつては同じ内容の日本語全文（52 行）がここにも重複しており、しかも `epic-commands/SKILL.md` の冒頭が「カノニカル参照はこの話題ファイルである」と名指していた — 1 つの規則を直すのに 2 か所へ同じ内容を書かせていたのはその 2 つであり、縮小にあたって列挙から `epic-plan.md` を外した。

**この話題ファイルは全体が 1 話題だったので、節の切り出しは要らずその場で縮小している**（joshuafolkken/kit#1186 が定めた「1 ファイルに複数の話題があるときは節を切り出してから縮小する」に該当しない側）。

**内容ではなく所在を書く。** 以下は畳み込みが漏れていないかを後から確かめるための索引であり、要約であっても本文を書けば複製になる。

参照文書だけにあったのは次の 6 件で、いずれも縮小の前に手順書へ畳み込み済みである。

- **短縮名** — `epic:plan` を打つもう 1 つの綴り
- **相 0 の整合監査が洗い出す 4 種** — 何を探しに行く工程なのか
- **見つけた矛盾の扱い** — Tier A で直すこと、根拠の記録先、相 2 の `ask` へ合流するのはどれか
- **相 0 が「省略可能な確認」ではない理由** — 人が指示して初めて矛盾が出る状態と無人実行の関係
- **トリアージ 3 分類の判定基準** — `auto` と `ask` を分けるのが何か
- **`auto` に分類したものをいつ記録するか** — 決めた時点ではなく実装時であること

手順書に置かれている内容:

- コマンドが 1 つの JSON として出力するもの（子の番号・タイトル・本文・ラベル・`blockedBy`・状態）
- 4 つの相の順序と、各相で何をするか
- 相 1 のトリアージ 3 分類（`auto` / `ask` / `defer`）とそれぞれの扱い
- 相 2 を EPIC 全体で 1 回にまとめる理由
- 回答を `## Decisions` と各子 Issue コメントの両方に記録する理由と、`## Decisions` の書式
- 決定を記録したら `needs-decision` を外すこと（解除規則そのものは `epicrun` 側の定義）
